1. INTRODUCTION
==============================================================

This report documents the design, implementation, testing, and
evaluation of a stack-based mathematical expression evaluator
developed for Assignment 1 of DCOMP320 - Data Structures and
Algorithm Analysis.

The program is written in Python and fulfils the assignment
requirement of implementing a Stack data structure from scratch
and using it to evaluate mathematical expressions. Expressions
are read from a plain text input file (input.txt), evaluated
using a custom algorithm, and the results are written to an
output file (output.txt) in a matching format.

The Shunting-Yard algorithm, originally described by Edsger W.
Dijkstra, is used to convert infix expressions (the standard
human-readable form, e.g. 3 + 5 * 2) into postfix notation
(Reverse Polish Notation, e.g. 3 5 2 * +). The postfix
expression is then evaluated using a second stack. This
two-stack approach cleanly demonstrates the Stack data
structure in a practical and academically meaningful way.

No built-in Python evaluation functions (such as eval()) were
used. Every component of the algorithm -- tokenisation, infix-
to-postfix conversion, and postfix evaluation -- is implemented
explicitly in the source code.

3. PROBLEM DESCRIPTION
==============================================================

The core problem addressed by this program is the evaluation
of infix mathematical expressions using a stack-based approach.

An infix expression is one where operators appear between
operands (e.g. 3 + 5 * 2). While this format is natural for
humans, it is not straightforward for computers to evaluate
directly because:

  - Operator precedence must be respected (* before +)
  - Parentheses can override the natural precedence
  - The expression must be scanned left to right

The classic computer science solution is the Shunting-Yard
algorithm, which uses a Stack to reorganise an infix expression
into postfix notation. Postfix notation is much easier for a
computer to evaluate because no precedence rules or parentheses
are needed during evaluation -- a simple stack-based scan
evaluates it correctly.

The input.txt file contains multiple expressions, each on a
separate line, with lines of five dashes (-----) acting as
separators between groups. The program must preserve this
structure in the output.

Example:
  Input line  :  3 + 5 * 2
  Output line :  13

4. DATA STRUCTURES USED
==============================================================

4.1  What is a Stack?
---------------------
A Stack is a linear data structure that stores items in a
sequential order. It is defined by one key constraint: all
insertions and deletions occur at the same end, called the
TOP of the stack.

A physical analogy is a stack of dinner plates: you can only
place a new plate on top, and you can only take a plate from
the top.

Diagram:
    PUSH / POP
        |
  +----------+
  |    30    |  <- TOP  (last pushed, first popped)
  +----------+
  |    20    |
  +----------+
  |    10    |  <- BOTTOM
  +----------+


4.2  Stack Operations
---------------------

  push(item)  -- Add item to the top.          O(1)
  pop()       -- Remove and return top item.   O(1)
  peek()      -- View top item, no removal.    O(1)
  is_empty()  -- True if stack has no items.   O(1)
  size()      -- Number of items in stack.     O(1)

Both pop() and peek() raise IndexError with a descriptive
message when called on an empty stack.


4.3  LIFO Principle
-------------------
LIFO = Last In, First Out.
The most recently added item is always the first removed.

Example:
  push(5), push(10), push(15)
  pop() -> 15,  pop() -> 10,  pop() -> 5


4.4  Importance of Stacks in Computing
---------------------------------------
Stacks are used in:
  - Expression evaluation and parsing (this assignment)
  - Function call stack (managing return addresses)
  - Undo/redo in text editors
  - Browser history (back/forward buttons)
  - Depth-first search in graph algorithms
  - Syntax checking in compilers

5.4  Algorithm Description
--------------------------
STAGE 1 -- TOKENISATION
  Scan character by character. Group digits into number
  tokens. Operators and parentheses are single tokens.
  Spaces are ignored. A leading minus sign (unary) is
  handled by inserting a '0' before it.

STAGE 2 -- SHUNTING-YARD (INFIX TO POSTFIX)
  Uses operator_stack (Stack). Rules per token:
    Number   --> append to output queue
    '('      --> push to operator_stack
    ')'      --> pop to output until '(' found; discard '('
    Operator --> pop higher/equal precedence operators first,
                 then push current operator

  Precedence:  * and / = 2  (higher)
               + and - = 1  (lower)

STAGE 3 -- POSTFIX EVALUATION
  Uses operand_stack (Stack). Rules per token:
    Number   --> push to operand_stack
    Operator --> pop two values, apply operator, push result
  Final answer = single value remaining on stack.

6. IMPLEMENTATION
==============================================================

6.1  Stack Class
----------------
Uses a Python list as backing store.
Index -1 is always the top (most recently pushed item).

  push(item)  -->  self._data.append(item)
  pop()       -->  return self._data.pop()
  peek()      -->  return self._data[-1]
  is_empty()  -->  return len(self._data) == 0
  size()      -->  return len(self._data)


6.2  Tokeniser
--------------
Single while loop with index pointer i. Multi-digit numbers
collected by scanning forward. Unary minus handled by
inserting '0': e.g. -5 + 10 becomes tokens 0 - 5 + 10.


6.3  Shunting-Yard Algorithm
-----------------------------
Example trace for  (8 / 4) + 7 * 2:

  Token  Action                 operator_stack  output_queue
  -----  --------------------   --------------  ------------------
  (      push                   [(]             []
  8      number->output         [(]             [8]
  /      push                   [(,/]           [8]
  4      number->output         [(,/]           [8,4]
  )      pop until (            []              [8,4,/]
  +      push                   [+]             [8,4,/]
  7      number->output         [+]             [8,4,/,7]
  *      *>+ so push            [+,*]           [8,4,/,7]
  2      number->output         [+,*]           [8,4,/,7,2]
  end    pop remaining          []              [8,4,/,7,2,*,+]

Postfix result: 8 4 / 7 2 * +


6.4  Postfix Evaluator
-----------------------
Example trace for  8 4 / 7 2 * +:

  Token  Action                 operand_stack
  -----  --------------------   ----------------
  8      push 8.0               [8.0]
  4      push 4.0               [8.0, 4.0]
  /      8/4=2.0, push          [2.0]
  7      push 7.0               [2.0, 7.0]
  2      push 2.0               [2.0, 7.0, 2.0]
  *      7*2=14.0, push         [2.0, 14.0]
  +      2+14=16.0, push        [16.0]

Result: 16


6.5  File Processing
---------------------
read_input_file() reads all lines, strips trailing newlines
and trailing empty lines.
process_expressions() preserves '-----' separator lines
and blank lines; evaluates everything else.
write_output_file() writes results one per line.


6.6  Main Entry Point
----------------------
main() orchestrates: read -> process -> print summary ->
write. Handles FileNotFoundError gracefully.
